# أركان المسار — Arkan Al-Masar

تطبيق حجز حافلات عربي/إنجليزي مع لوحة إدارة وواجهة للسائق، مهيأ في هذا الفرع للنشر المستقل على **Cloudflare Workers + D1**. مستودع GitHub يحفظ الكود وملفات إنشاء الجداول فقط؛ لا يحتوي بيانات قاعدة الموقع الحالي أو كلمات المرور.

## الموجود في المشروع

- بحث جدة ↔ مكة، اتجاه واحد أو ذهاب وعودة، محطات ومواعيد وأسعار قابلة للإدارة.
- خريطة 49 مقعداً لكل حافلة، اختيار مستقل لكل اتجاه، وحجز مؤقت ذري للمقاعد لمدة 10 دقائق.
- بيانات المسافرين والجنسية، شروط الحجز، استرجاع الحجز بالرقم والجوال، وملخص PDF مع QR وإخفاء جزء من رقم الهوية.
- حسابات بإيميل وكلمة مرور للإدارة وموظف الصعود والسائق، مع صلاحيات في الخادم.
- إدارة الرحلات اليومية والمتكررة والحافلات والسائقين وتعيينهم للرحلات، وكشف ركاب قابل للطباعة/PDF وتقارير.
- واجهة سائق للرحلات المخصصة له، فحص QR أو إدخاله يدوياً، وبدء الصعود والانطلاق والوصول مع تسجيل الموظف والوقت.
- إشعارات داخل التطبيق وWeb Push. يلزم تفعيل الإشعارات من الأجهزة واختبار الاستلام عليها؛ لا يوجد تتبع GPS.

**حالة البيع:** بوابة الدفع الفعلي والاسترداد الآلي وإرسال WhatsApp والبريد آلياً لم تُربط بعد. `BOOKING_MODE=demo` اسم داخلي يسمح بإنشاء طلبات غير مدفوعة؛ تغيير المتغير لا يفعّل الدفع. فحص تذاكر الطلبات غير المدفوعة يرفض الصعود. توجد حالة فحص محددة طلبها المالك سابقاً في `lib/checkin-trial*`؛ ليست نموذجاً لتذاكر مدفوعة.

الأسعار الابتدائية 15 ر.س للاتجاه الواحد و30 ر.س للذهاب والعودة، قابلة للتعديل. عند إنشاء قاعدة جديدة تظهر محطات وجداول وحافلات ابتدائية؛ راجع بيانات التشغيل الحقيقية من لوحة الإدارة قبل استقبال العملاء.

## المتطلبات

Node.js 22.13 أو أحدث، ونسخة pnpm المثبتة في `packageManager` داخل `package.json`. حافظ على `pnpm-lock.yaml` واستخدم:

```sh
pnpm install --frozen-lockfile
```

النسخة تستخدم vinext وVite وCloudflare Vite plugin بالإصدارات المثبتة. لا يحتاج تشغيلها إلى هوية ChatGPT أو إعدادات نشر Sites. بعض ملفات سير عمل Sites محفوظة من المصدر ولا يستعملها البناء المستقل.

## ربط Cloudflare لأول مرة

نفذ الأوامر من جهاز موثوق في حساب Cloudflare الذي سيستضيف المشروع:

```sh
pnpm exec wrangler login
pnpm exec wrangler whoami
pnpm exec wrangler d1 create arkan-al-masar-db
```

انسخ `database_id` الفعلي الناتج، ثم أدخله مع بريد التواصل المخصص للإشعارات أو رابط صفحة التواصل على نطاقك. القيم التالية أمثلة يجب استبدالها:

```sh
pnpm config:cloudflare --database-id YOUR_D1_UUID --vapid-subject mailto:YOUR_CONTACT_EMAIL
```

ملف `wrangler.json` المرفق يحتوي معرف قاعدة صفرياً و`VAPID_SUBJECT` فارغاً عمداً. أمر النشر يتوقف حتى تُضبط القيم الحقيقية. معرف القاعدة وعنوان التواصل ليسا أسراراً؛ يمكن حفظهما في المستودع. لا تحفظ رموز Cloudflare أو GitHub أو نسخ قواعد البيانات فيه.

### قاعدة جديدة

```sh
pnpm db:migrate:remote
pnpm owner:setup --remote
```

الأمر الثاني يطلب إيميل المالك واسمه وكلمة مرور مخفية مرتين، ويعمل فقط في طرفية تفاعلية. كلمة المرور 12–128 حرفاً. ينشئ حساب المالك مرة واحدة، ويرفض استبدال حساب موجود. لا تضع كلمة المرور في الأمر أو GitHub أو ملفات البيئة. بعدها أضف حسابات الإدارة والموظفين والسائقين من `/admin` واربط حساب السائق بسجله.

إنشاء حساب المالك أو استعادته عبر HTTP معطل في هذا الفرع؛ لا توجد كلمة مرور افتراضية أو ترويسات هوية موثوقة من المتصفح. الحسابات الحالية وكلمات مرورها تظل صالحة إذا نُقلت قاعدة البيانات نقلاً صحيحاً. استرجاع كلمة مرور المالك المفقودة يحتاج إجراءً إدارياً منفصلاً ومراجَعاً على قاعدة البيانات، وليس إنشاء مالك ثانٍ.

### نقل بيانات الموقع الحالي

**رفع الكود أو تطبيق migrations لا ينقل الحجوزات ولا حسابات السائقين والإدارة.** قبل تحويل أي نطاق، احصل على تصدير آمن لقاعدة Sites الفعلية، ثم اختبر استيراده إلى قاعدة Cloudflare مستقلة وتحقق من الأعداد والعلاقات والحسابات. لا تستخدم قاعدة `.wrangler` المحلية باعتبارها الإنتاج.

اختر مسار الاستيراد بحسب محتوى النسخة: إن كانت تشمل الجداول، لا تطبق إنشاء الجداول فوقها عشوائياً؛ وإن كانت بيانات فقط فأنشئ المخطط المطابق أولاً. حافظ على كلمات المرور المشتقة دون طباعتها أو تغييرها. لا ترفع أرقام الهويات والجوالات أو رموز التذاكر والجلسات أو مفاتيح Push إلى GitHub. احتفظ بالنسخة في مكان خاص خارج المستودع.

ابدأ انتقالاً منظماً بعد التحقق، مع إيقاف الكتابة على المصدر لفترة النقل النهائية لتجنب حجوزات متعارضة. اترك الموقع القديم متاحاً حتى التأكد من النسخة الجديدة. الإشعارات على النطاق الجديد تحتاج اشتراك الأجهزة من جديد. لم تُنقل بيانات الإنتاج ضمن تجهيز هذا الفرع.

## البناء والنشر

```sh
pnpm build
pnpm exec tsc --noEmit
pnpm deploy
```

ينتج البناء `dist/server/index.js` و`dist/server/wrangler.json` وملفات الواجهة في `dist/client`. يتحقق أمر النشر من معرف D1 وعنوان VAPID وتطابق إعدادات البناء، ثم يستعلم عن وجود مالك فعال قبل نشر Worker. لذلك يحتاج حساب/رمز النشر صلاحية قراءة D1 إضافة إلى نشر Workers. لا تنفذ migrations تلقائياً مع كل نشر؛ راجعها وطبق المطلوب قبل النسخة التي تعتمد عليها.

لإجراء فحص إعدادات فقط دون اتصال أو نشر:

```sh
node scripts/deploy-cloudflare.mjs --check-config-only
```

بعد النجاح، افتح رابط Worker الذي يعيده Cloudflare وتحقق من `/` و`/admin` و`/driver` و`/my-bookings`، ثم اختبر دخول الأدوار وتعارض المقاعد وQR والإشعارات من أجهزة فعلية. هذا المشروع يحتاج Worker مع D1، وليس رفع `dist/client` وحده إلى Pages كملفات ثابتة.

## الربط التلقائي مع GitHub

ارفع الفرع المجهز إلى مستودع خاص، ثم اربطه من Cloudflare Workers Builds. اختر الفرع الذي يحتوي هذه الإعدادات، واجعل مجلد الجذر هو جذر المستودع:

- أمر البناء: `pnpm build`
- أمر النشر: `pnpm deploy`
- اسم Worker: `arkan-al-masar` مطابقاً لملف Wrangler.

استخدم النسخة المحددة من pnpm وNode، واضبط تثبيت الحزم بـ`pnpm install --frozen-lockfile`. يجب أن تكون قاعدة D1 والمخطط وحساب المالك مجهزة قبل أول نشر تلقائي. احفظ بيانات اعتماد البناء داخل Cloudflare ولا تُضمنها في الكود. اسم المستخدم والمستودع وروابط النشر النهائية تُحدد بعد الاتصال بالحسابات؛ ليست منشأة بمجرد وجود هذه الملفات.

## التطوير المحلي

```sh
pnpm db:migrate:local
pnpm owner:setup --local
pnpm dev
```

استخدم ملف `.dev.vars` محلياً لإعداد `VAPID_SUBJECT` أثناء اختبار الإشعارات. قاعدة D1 المحلية معزولة عن البعيدة، و`--local` و`--remote` صريحان في أوامر الإدارة. `pnpm start` يشغل ناتج البناء محلياً. جلسات الإدارة تستخدم Cookie آمنة؛ استخدم localhost أو HTTPS للتجربة، ولا تضعف خصائص Cookie لأجل شبكة محلية غير مشفرة.

## الملفات والأصول

المخطط في `db/schema.ts`، وملفات migrations في `drizzle/` وتظل تراكمية. جميع الصور والخطوط محلية؛ الخط الأساسي Alexandria وخط PDF المضمن DejaVu Sans. `.gitignore` يستبعد ملفات البيئة والأسرار والحزم ونواتج البناء ونسخ البيانات؛ الملفات الموجودة في Git سابقاً لا يحميها الاستبعاد تلقائياً، لذلك راجع محتوى أي commit قبل الرفع.
